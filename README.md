# E4 · Исполнение полудуплексных протоколов

Основной ноутбук — [reproduction.ipynb](reproduction.ipynb). В нём описан эксперимент,
выбираются настройки, показываются входы и промпт, запускаются проверки и строятся графики.
Вычисления и работа с моделями находятся в пакете `halfduplex`.

## Эксперимент

Проверяем, насколько точно языковая модель исполняет **заранее объяснённый алгоритм
обмена**, используя только свой вход и доступные ей наблюдения. Алиса получает
битовую строку `x` длины `n`, Боб — строку `y` той же длины. Оба должны вычислить один бит:

| `task` | Функция | Когда ответ равен 1 |
|---|---|---|
| `ip` | Inner Product, скалярное произведение по модулю 2 | Число позиций с двумя единицами нечётно |
| `eq` | Equality, равенство | `x == y` |
| `disj` | Disjointness, непересечение | Общих единичных позиций нет |

В каждом раунде игроки независимо выбирают `SEND_0`, `SEND_1` или `LISTEN`.
Если отправляет один, бит получает слушатель. При двух отправках биты теряются,
а отправители не узнают о столкновении. Если оба слушают, канал `silence` даёт
специальный символ `SILENCE`, канал `zero` — обычный бит 0.
Итоговые `ANSWER_0`/`ANSWER_1` не передаются другому игроку и не расходуют раунд;
игроки должны завершить обмен одновременно.

| `experiment` | Что запускаем | Что измеряем |
|---|---|---|
| `episode` | Полный обмен; у каждой роли своя беседа, продолженная после каждого раунда | Верность обоих ответов (`joint_accuracy`), точное исполнение (`exact_execution`), число раундов |
| `step` | Независимый запрос для каждого уникального локального состояния эталонных траекторий | Точность действий и ответов по отдельности и вместе (`decision_accuracy`) |

В `step` история задана программным эталоном; в `episode` дальнейшие решения
опираются на реальные действия игроков. Правильный итоговый бит и точное следование
алгоритму оцениваются отдельно. Это реализация E4 из
[постановки проекта](<communication_complexity_final (1).html>).

## Генерация входов

Всего существует `4**n` пар `(x, y)`. Генератор использует `random.Random(seed)`;
`case_limit` задаёт число разных пар, `repeats` — число повторов на тех же входах.

- **`sampling="uniform"`**: равномерная выборка пар без повторений. При обычных
  размерах выбираются индексы `i` из `0..4**n-1`, затем `x, y = divmod(i, 2**n)`;
  числа записываются в двоичном виде ровно `n` битами. Для больших пространств
  используется равномерная генерация индексов с отбрасыванием повторов.
- **`sampling="eq_balanced"`**: выборка для EQ. Сначала выбираются
  `ceil(case_limit/2)` разных равных пар, затем — остальные неравные пары без повторений;
  порядок перемешивается. При размере 15 это 8 равных и 7 неравных пар.
  В равномерной выборке вероятность равенства всего `2**(-n)`, поэтому два
  распределения дают разные условия эксперимента.
- **Одна заданная пара**: `case_limit=None, case=("00111", "00100")` при `n=5`.

При одинаковых `n`, `seed`, `sampling`, `case_limit` и `case` смена алгоритма,
моделей, формата входа или объяснения сохраняет пары и их порядок. Так можно
сравнивать запуски на одинаковых данных. Форматы `bits`, `bit_list`, `positions`
меняют только представление входа в промпте; позиции единиц нумеруются с 1 слева.

## Алгоритмы

`task` выбирает функцию, `channel` — канал, `protocol` — способ обмена:
`baseline` или `specialized`. Конкретная реализация сохраняется в поле `implementation`.

| `protocol` | Реализация | Функция / канал | Максимум раундов |
|---|---|---|---|
| `baseline` | `send_x_then_result` | IP, EQ, DISJ / оба канала | `n+1` |
| `specialized` | `ip_silence` | IP / `silence` | `ceil(n/2)+2` |
| `specialized` | `eq_silence` | EQ / `silence` | `k+w+2`, `k=ceil(n/log_2(5))`, `w=ceil(log_3(k+1))` |
| `specialized` | `eq_zero` | EQ / `zero` | `k+2*w+1`, `k=ceil(n/log_2(3))`, `w=ceil(log_2(k+1))` |

- **Передача входа и результата (`send_x_then_result`)**. Алиса передаёт весь `x`
  по одному биту; Боб вычисляет выбранную функцию по `x` и своему `y`, затем
  отправляет результат Алисе. Универсальный базовый алгоритм.
- **IP по парам битов с тишиной (`ip_silence`)**. При нечётном `n` справа добавляется
  ноль. Игроки обрабатывают пары битов по таблице отправки/слушания и накапливают
  локальные биты. Затем Алиса передаёт свой аккумулятор, Боб объединяет его со
  своим через XOR и возвращает ответ.
- **EQ в основании 5 с тишиной (`eq_silence`)**. Входы кодируются пятеричными
  цифрами. Полученные символы проверяются на совместимость с равными цифрами;
  флаг несовпадения позволяет завершить обмен раньше, за `k+1` раундов.
  Иначе Алиса передаёт число принятых битов в основании 3, Боб сравнивает его
  с числом своих отправок и возвращает ответ. Счётчик обнаруживает скрытые столкновения.
- **EQ в основании 3 с нулём (`eq_zero`)**. Входы кодируются троичными цифрами.
  После основной фазы оба передают двоичные счётчики своих отправок и сверяют их
  с числом полученных единиц. Итоговый флаг несовпадения определяет ответ.

Оценки включают завершающий обмен и счётчики с достаточной шириной для значений
`0..k`. При малых `n` специализированная схема может быть дороже базовой.
Для DISJ и для IP с каналом `zero` доступен только `baseline`.
Прежние значения `protocol` (`ip_silence`, `eq_silence`, `eq_zero`,
`send_x_then_result`) продолжают читаться из конфигураций и журналов.

Источники: IP — [Dementiev et al., ECCC TR26-112, теорема 3](https://eccc.weizmann.ac.il/report/2026/112/download/);
EQ — [Hoover et al., ECCC TR18-089, редакция 2, теоремы 6 и 10](https://eccc.weizmann.ac.il/report/2018/089/revision/2/download/).

## Промпт модели

Используем шаблон из [halfduplex/prompts.py](halfduplex/prompts.py). Он содержит
роль, функцию, правила канала, лимит раундов, инструкцию выбранного алгоритма,
**только свой вход**, доступную локальную историю и требование вернуть один токен.
`explanation="prose"` задаёт словесное объяснение; `"pseudocode"` дополнительно
включает локальное правило на Python.

В `episode` первая инструкция открывает отдельную беседу роли, затем модель
получает своё действие и наблюдение за последний раунд. В `step` каждый запрос
содержит полную заданную локальную историю и не продолжает предыдущую беседу.

Пример **полного стартового промпта Алисы** при `n=5`, IP, `silence`,
`specialized`, `prose`, `bits`, `allow_python=True`; её вход `00111` — из первой
пары при `seed=42`, `sampling="uniform"`, `case_limit=15`:

```text
Ты исполняешь роль Alice в полудуплексном протоколе. n=5.
Alice знает только x, Bob знает только y. IP: чётность числа позиций с двумя единицами.
В раунде оба независимо выбирают SEND_0, SEND_1 или LISTEN.
Если отправляет один, бит получает слушатель; у отправителя наблюдение «нет».
Если отправляют оба, биты теряются; оба наблюдают «нет», столкновение им не сообщается.
Если слушают оба, каждый наблюдает специальный символ SILENCE.
ANSWER_0/ANSWER_1 — отдельное итоговое решение без передачи по каналу. Оба должны
завершить одновременно по правилам протокола. Любой SEND/LISTEN стоит один раунд.
Лимит: 5 раундов. Наблюдения 0, 1, SILENCE и «нет» различаются.

Протокол specialized (ip_silence):
Если n нечётно, допиши справа один нулевой бит. Разбей свой вход на пары.
Пусть k=ceil(n/2). Первые k раундов обрабатывают по одной паре.
Таблица Alice: 00 -> SEND_0; 01 -> SEND_1; 10 -> LISTEN; 11 -> LISTEN.
Таблица Bob:   00 -> SEND_0; 01 -> LISTEN; 10 -> SEND_1; 11 -> LISTEN.
Локальный аккумулятор изначально 0. После каждого из этих раундов:
для пары 00 ничего не меняй; для 01 или 10 инвертируй аккумулятор только
при наблюдении 1; для 11 инвертируй, если наблюдение НЕ равно 0, включая SILENCE.
В раунде k+1 Alice отправляет свой аккумулятор, Bob слушает.
В раунде k+2 Bob отправляет XOR полученного бита и своего аккумулятора,
Alice слушает. Затем оба отвечают этим результатом.

Твой приватный вход: 00111
Формат: Битовая строка; старший бит слева. Восстанови свою строку длины n локально.

Сейчас нужно решение для позиции 1. Применяй заданные правила,
включая локальные условия остановки. При продолжении беседы сохраняй свою историю.
Можно использовать инструмент python для локальных вычислений. Интернет недоступен.
Верни ровно один токен: SEND_0, SEND_1, LISTEN, ANSWER_0 или ANSWER_1.
Без пояснений, кавычек и Markdown.
```

В ноутбуке перед запуском выводится фактический промпт для текущих настроек.
При `allow_python=True` модели доступен только инструмент `local_python.python`
в bubblewrap: без сети, файлов проекта, чужих сессий и среды хоста. Веб-поиск,
терминал, приложения и дополнительные агенты отключены. Сеть самого CLI нужна
для обращения к модели. При недоступной изоляции запуск останавливается до запроса.

## Запуск

Нужен Python 3.10+. Для LLM-запусков также нужны Linux/WSL, Codex CLI,
вход через `codex login`, `bubblewrap` (`sudo apt install bubblewrap` в Ubuntu)
и `/usr/bin/python3`. Адаптер использует файловый `auth.json`; пользовательские
настройки CLI не загружаются. Для графиков установи в окружение ядра:

```bash
python3 -m pip install -r requirements-plots.txt
```

Открой `reproduction.ipynb` из корня проекта и выполняй ячейки по порядку:
настройки → входы и промпт → программный эталон → запуск → отчёт и графики.
Начальные настройки ноутбука:

```python
from halfduplex import RunConfig, PlayerConfig, run_experiment

config = RunConfig(
    task="ip", channel="silence", protocol="specialized", n=5,
    experiment="episode",       # episode или step
    alice=PlayerConfig(backend="codex", model=None, allow_python=True),
    bob=PlayerConfig(backend="codex", model=None, allow_python=True),
    sampling="uniform", case_limit=15, seed=42, repeats=1,
    explanation="prose", input_format="bits", output_dir="runs",
)
```

`model=None` означает встроенный выбор CLI; для воспроизводимых сравнений
укажи точное имя модели отдельно у каждой роли. `backend="python"` выбирает
программный эталон, `"manual"` — ручной ввод. `round_limit` задаёт отдельный бюджет связи.
Для EQ выбери `task="eq"` и при необходимости `sampling="eq_balanced"`.
Для сравнения с базовым обменом поменяй только `protocol="baseline"`.

Для начала прогона включи флаг в ячейке запуска:

```python
RUN_EXPERIMENT = True
result = run_experiment(config) if RUN_EXPERIMENT else None
```

По умолчанию в файле флаг `False`: просмотр входов, промпта и эталона не вызывает
модель. `RUN_TOOL_AUDIT=True` отдельно включает проверку реального вызова Python;
`PLOT_RESULTS=True` строит графики по сохранённому журналу.

Из терминала можно проверить эталон или запустить готовую конфигурацию:

```bash
python3 -m halfduplex reference --task ip --channel silence --protocol specialized --n 5
python3 -m halfduplex run --config configs/eq_silence.json
python3 -m halfduplex run --config configs/eq_zero.json --python-players
```

В `configs/` также есть `ip_silence.json`. Параметры CLI `--alice-model`,
`--bob-model`, `--limit` переопределяют настройки запуска; `--python-players`
выбирает программных игроков. Отдельный аудит инструмента: `python3 -m halfduplex audit-tools`.

## Результаты и проверки

Каждый запуск создаёт отдельный каталог `runs/e4_.../`:

| Файлы | Содержание |
|---|---|
| `manifest.json`, `source/` | Настройки, пары, версии, политика инструментов и снимок кода |
| `journal.jsonl` | Исходные эпизоды или отдельные решения |
| `events.jsonl`, `calls/`, `sessions/` | Ходы, наблюдения, промпты, ответы, usage, ошибки и сессии CLI |
| `report.jsonl`, `summary.json` | Пересчитанные метрики, включая точность отдельно по классам ответа в `episode` |

Отчёт отделяет неверный формат, действие, фазу и ответ. Число раундов на выборке
(`max_observed_rounds`) отличается от максимума по полному перебору (`c_max`).
При прерывании готовые данные сохраняются; незаконченный прогон отмечается
`run_complete=false`. Секреты авторизации в журналы не копируются.

```python
from halfduplex import analyze_file, plot_results

summary = analyze_file("runs/e4_.../journal.jsonl")
figure = plot_results("runs/e4_.../journal.jsonl", save_path="plots.png")
```

Локальная проверка: `python3 -m unittest discover -v`. Реальную изоляцию ОС и MCP
проверяет `python3 scripts/validate_runtime.py` в среде, допускающей пространства имён Linux.
При проверке 14 ноября 2026 все 35 тестов прошли; специализированные эталоны
проверены на всех парах для `n=1..6`, дополнительно — 432 эпизода при `n` до 1024.
Ноутбуки, CLI и графики также проверены. Перебор подтверждает конечные размеры;
основания корректности для произвольного `n` даны в статьях.

Исторические журналы, отчёты и графики лежат в [results/](results/), графики
названы по соответствующему прогону. Более ранний прогон — IP, `n=3`, Python–Codex.
Сохранённый пилот: IP, `n=5`, `baseline`, Codex–Codex — 15/15 правильных ответов
и точных исполнений, по 6 раундов. Отдельный реальный пробный запуск IP, `n=2`,
`specialized` завершился точно за 3 раунда. Точность LLM для новых EQ пока не измерена.
Старые журналы поддерживаются; версии пилотного ноутбука находятся в
[archive/experiment4_7.ipynb](archive/experiment4_7.ipynb) и
[archive/experiment4_7_pilot.ipynb](archive/experiment4_7_pilot.ipynb).
